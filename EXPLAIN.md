# Как устроена система

**Что это.** Сайт, где руководитель (постановщик) заводит стройки и ставит по ним задачи конкретным работникам (исполнителям). Исполнитель берёт задачу в работу и, когда закончил, отправляет на проверку. Постановщик либо принимает работу, либо возвращает на доработку и обязательно пишет, что не так. Каждый такой шаг сохраняется: кто, когда, из какого статуса в какой и с каким комментарием. Эту историю видят оба.

**Где хранятся данные.** Сайт только показывает данные. Сами данные лежат в базе данных Supabase, это облачный сервис с базой данных и входом по паролю. Любой человек технически может обратиться к базе напрямую, минуя сайт, поэтому все правила доступа записаны в самой базе, а не в кнопках сайта. Если исполнитель попробует отправить запрос вручную, база ответит отказом так же, как если бы кнопки просто не было.

**Как защищены данные.**

- Войти можно только по email и паролю, которые выдал администратор. Самостоятельная регистрация выключена.
- Роль (постановщик или исполнитель) хранится в базе, и изменить её может только администратор. Сам себе роль поднять нельзя.
- Для каждой таблицы в базе задано правило, какие строки видит каждый пользователь (это называется RLS, «защита на уровне строк»). Например, исполнитель при любом запросе получает только свои задачи.
- Статус задачи меняется только через одну проверяющую функцию в базе. Она смотрит, кто просит, назначен ли он на эту задачу и разрешён ли такой шаг. Заодно она сама пишет запись в историю.
- Историю никто не может дописать, исправить или стереть через сайт или напрямую, даже постановщик. Она пополняется только автоматически.
- Секретный ключ администратора базы нигде в сайте и в коде не хранится. На сайте только публичный ключ, который сам по себе ничего не открывает без входа.

**Что не может исполнитель.**

- Видеть чужие задачи, их историю и объекты, где у него нет задач. Чужая задача для него выглядит как несуществующая.
- Создавать, удалять или редактировать задачи и объекты: менять название, описание, объект или исполнителя.
- Перескочить через шаг (например, сразу из «Новая» в «Принята»), сам принять свою работу или вернуть её на доработку.
- Трогать принятую задачу.
- Подделать или удалить запись в истории.
- Назначить себя постановщиком.

Всё перечисленное проверено автоматически: отдельный проверочный скрипт поднимает такую же базу и пытается сделать каждое из этих действий в обход сайта. Все 46 проверок проходят.
